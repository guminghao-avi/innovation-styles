# 叙事模板：大问题 + 历史接力 + 叠加悬念

来源：对 B 站《运气的形状》的历史拆解笔记。原参考视频及实战工程不随本 skill 分发；本文只提供叙事骨架，不将笔记中的例子当作已核实史料。

**适合**：一个概念在历史上被一代代人追问、修正的题目，比如概率、命运、光、时间、无穷、地图、货币。
**不适合**：没有"人物 + 年代 + 难题"可接力的纯意境、纯抒情题目。

## 骨架

```
【冷开场】1 句：一个悬而未决的具体瞬间（骰子没落地 / 线头前面一片空白）
【总问题】1 句：把瞬间升成一个大问题，关键词高亮（"运气，能被计算吗？"）
【片名】主标题 + 一句承诺式副标题（"人类如何把偶然写进数学"）
【旧世界】1–2 句：过去的人怎么看这件事，推到最极端（"掷骰子是在向神发问"）
【第 N 站】年份 · 地点 · 人物 · 出处
    场景（具体数字 / 物件）→ 难题 → 某人的答案 → 质疑（"真的公平吗？"）
    质疑就是交给下一站的钩子
【收束】最后一两站一次性解开所有悬念，回答总问题
【回到开场】回到开场那个瞬间 / 物件，落到"你"身上
```

## 八条手法

1. **悬念叠着开，不要开一个关一个**。观众手里始终攥着 1–3 个没解开的问题。
   - 短线（几句后就揭晓，先让观众尝到一次爽）："哈雷没等到 1758 年" → "它准时回来了"
   - 长线（跨站）："这道题一悬就是 160 年" / "答案藏在 75 年后的一场生日悬赏里"
   - 写剧本前先列一张悬念表：每个悬念在哪句开、在哪句收。写进 brief.md。
2. **每站四拍**：场景 → 难题 → 答案 → 质疑。不要一站只讲"某人发现了某事"。
3. **具体数字和具体物件，不讲概念**。不说"分配问题"，说"甲 50 乙 20，先到 60 赢"。不说"敏感依赖"，说"0.506127 输成了 0.506"。
4. **先让观众自己得出结论，再用事实推翻**："9 点和 10 点都是 6 种组合" → "可 10 点更常出现"。
5. **人物带一个反差标签**："嗜赌的医生卡尔达诺"、"德累斯顿的一位农夫"、"他去喝了杯咖啡"。
6. **一句一个镜头，画面替这句话演**。说"中断"，红印就盖下来；说"5:2"，金币就被切开；说"真的吗"，问号就冒出来。没有只为好看的镜头。
7. **一个物件贯穿全片，每个时代换一种形态**（骰子：羊距骨 → 命运之轮 → 金币 → 展开图；金线：纺锤 → 轨道 → 织物 → 三体 → 蝴蝶）。形态之间用形变转场。
8. **档案卡给可信度**：每站左上角固定一张卡，写年份（滚动到下一站）、地点·人物、原书名 + 中文名。年份滚动本身就是"时间在接力"的转场。

## 写剧本时的硬规矩

- **每句 12–20 字**，一句一个意思。字幕即叙事时，每句停留时长 ≈ 0.95 + 字数 × 0.125 秒，约 5 字/秒。
- **关键词高亮**：在 vo.json 里写成 `**词**`，每句最多一个，一般高亮数字或点题词。
- **立意要准**：收束句经得起推敲。例如混沌推翻的是"未来能被算出来"，不是"规律是确定的"，所以落点是"剧本也许有，但读不完"，不是"命运不存在"。
- **史实必须查证**（WebSearch），查不到出处的具体数字宁可换成稳妥说法。例如"3585 克朗"查无出处，改成"比奖金多出约 1000 克朗"。演示用的数字尽量用真实值，比如洛伦兹的 0.000127 直接代入算，不为效果放大。
- **控制时长**：先跑 `scripts/silent.py`（或 `voice.py`）看总长，超了优先删去次要信息或拆成两条片子；`perChar` 根据实际可读性调整，不靠加速把字幕塞进去。

## 动手前写清楚的东西

动手做画面之前，把三样东西写进 `brief.md`：
1. 总问题和立意（一句话）
2. 逐句剧本（标出每站和每句的叙事功能）
3. 悬念表

用户要求先审剧本时，提交这些内容等待回复；用户已经要求直接制作时，说明关键选择并继续。只在关键事实无法确认或用户要求冲突时提问。
