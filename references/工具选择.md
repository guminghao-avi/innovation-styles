# 按画面需求选择工具

风格决定画面长什么样，工具决定怎样把它做出来。先在 `brief.md` 记录关键效果、采用的工具和交付命令，再制作。用户指定工具时先按其要求评估；不要因为示例用 Remotion 就要求每部新片也用它。

## 选择与切换

| 关键需求 | 起步方案 | 何时切换 |
|---|---|---|
| 字幕、图形、像素、手绘、剪纸、HUD、几何形变 | 现有 Remotion + React / Canvas / GLSL | 需要复杂模型、真实物理或更精细的光照时，把对应镜头交给三维工具 |
| 可旋转的简单模型、相机和空间关系 | Three.js；要接入现有时间轴时用 `@remotion/three` | 软件渲染负载过高，或关键材质/运动无法满足参考时，先试离线渲染 |
| 建模、复杂材质、全局光照、刚体或流体模拟 | Blender 等离线三维工具 | 先检查本机可用工具、版本和算力，用短片测质量与耗时；缺少依赖时说明所需环境 |
| 三维镜头叠字幕、二维图形、声音 | 三维先渲序列帧/视频，再用 Remotion 或 FFmpeg 合成 | 根据可编辑性和时间轴复杂度选合成工具，不必重做已渲好的三维画面 |

这些是选择建议。仓库已经提供的是 **19 套 Remotion 示例**；没有附带 Blender 工程、流体模拟器或通用的多工具执行器。Three.js 依赖已列在 `package.json`，具体场景仍需实现和验证。[Remotion 的三维集成](https://www.remotion.dev/docs/three/)说明了 ThreeCanvas 与按帧动画的接入方式。

## 两个容易混淆的示例

- `soft3d`：SDF 光线步进绘制胶囊、铬球、软阴影和 AO；球的弹跳由解析函数计算，周围胶囊用程序波纹变形。它没有做物体之间的刚体碰撞、真实软体形变或路径追踪。需要这些效果时，另外制作离线三维镜头。
- `liquid`：二维距离场的平滑并集，加高光与倒影，表现融合、拉丝和字标。它没有做真实三维流体模拟；复杂液体飞溅、折射和镜头绕拍需要其他实现。

先试最能体现差别的 1–3 秒镜头。画面达不到要求就换方案，不把简化实现宣称成已经还原了参考的全部效果。也不要按风格文档中的历史速度估计本机耗时。

## 工程怎样留下来

- Remotion 路线：使用 `Main.tsx`、`vo.timing.json`、共享节拍及需要的声音配置，按 [制作与验收](制作与验收.md) 运行。
- 离线三维路线：在项目目录保留实际用到的 `.blend`、生成脚本、素材、时间/FPS 设置和渲染命令；写明模拟缓存的生成顺序。不要求创建空的 `Main.tsx`。
- 混合路线：记录源镜头的起始帧、FPS、总帧数、分辨率及透明通道需求，再进入合成。避免靠猜时长或无意变速对齐。需要透明叠层时先确认中间格式保留 alpha。

所有路线都先检查代表静帧和连续运动，再核对最终媒体的尺寸、FPS、帧数、音轨和完整解码。学习新风格时，沉淀实际用过并验证的工程、脚本或组件；参考标签只能作为线索。
