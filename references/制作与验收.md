# 制作与验收

所有路径以当前 skill 根目录为准。示例中的 `P` 代表 `projects/` 下的一个目录名，命令中替换为真实名字；名字有空格时加引号。

## 环境与首次检查

需要 Node.js 22.18+（推荐 24）、Python 3.10+、FFmpeg/ffprobe；Remotion 首次渲染需要联网下载 Chrome Headless Shell。

```bash
npm ci
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm run check
```

Windows 用 `.venv\Scripts\python.exe` 替换 `.venv/bin/python`。运行脚本本身不要求 GPU；着色器默认用 `swangle` 软件渲染。速度取决于机器和画面复杂度，先用几张静帧或 1–3 秒测试片估时。

直接预览默认纸艺示例：

```bash
npm run studio
```

选择其他项目（Bash/Zsh）：

```bash
PROJ='示例_潜水戴夫风' npm run studio
node scripts/check.mjs --proj '示例_潜水戴夫风'
```

PowerShell 用 `$env:PROJ='示例_潜水戴夫风'; npm run studio`。`check.mjs` 生成项目专用临时配置，逐个检查 `@proj` 引用；无需手动改共享 `tsconfig.json`。

## 一部新片的文件

| 文件 | 用途 |
|---|---|
| `brief.md` | 核心意思、风格、母题、镜头表、事实来源 |
| `Main.tsx` | 导出 `Main` 和 `DURATION`（秒）；使用 `@kit` 和选定的风格包 |
| `vo.json` / `vo.timing.json` | 字幕源文件 / 生成的时间轴 |
| `beats.json` | 多个镜头或声音共用的时间锚点 |
| `gen_sound.py` / `sound.json` | 可复现的声音编排 / 声音合成输入 |
| `post.json` | 调色、辉光、颗粒等；按风格示例起步 |
| `public/` | 用 `staticFile()` 引用的项目素材；字体已经在根目录打包 |

最小字幕输入：

```json
{
  "start": 0.1,
  "gap": 0.5,
  "base": 0.9,
  "perChar": 0.12,
  "lines": [
    {"id": "a1", "text": "等来的回应，还是**零**。", "hold": 0.4},
    {"id": "a2", "text": "那就先造一块，能浮起来的木板。", "gap": 1.0}
  ]
}
```

```bash
.venv/bin/python scripts/silent.py P
```

`gap` 是这句之前的停顿，`hold` 是这句多停的时间，`at` 可用绝对秒数（字幕模式只接受数字）。ID 必须唯一；负值、无效数字、重叠字幕会报错。`silent.py` 只生成时间轴，不生成声音；修改文案后先重跑，再改共享节拍。

`beats.json`：

```json
{"build": "a2+0.4", "title": "a2.end+1.2"}
```

TS 用 `makeVO(timing, beats)`，Python 用 `Resolver(project_dir).time`。两端都支持开始、`.end`、`@关键词`、`@关键词.end`、命名节拍、数字和 `+/-` 秒偏移；关键词有多处时取第一处。不要用 `a1.end` 作为节拍名，也不要让节拍循环引用。

## 静帧与视觉检查

```bash
node scripts/check.mjs --proj P
node scripts/render.mjs --proj P --stills 0,1.2,8.4
node scripts/render.mjs --proj P --stills 8-9/6
```

每次静帧保存在新的 `stills/<批次>/` 下，包含原始图、后期图和 `sheet.png`；项目根目录 `sheet.png` 是最新总览。旧静帧保留，方便对比。`--raw` 可跳过后期。时间必须在片长内，单次最多 100 帧。

打开总览后，关键帧再看原尺寸：开头能否马上理解事件，字幕是否被遮住，UI 与主体是否打架，光是否盖住像素，读数是否跟位置/状态一致。发现问题就修改并复查受影响的镜头和转场。

## 声音

先借选定风格的 `gen_sound.py` 编排声音，再运行：

```bash
.venv/bin/python projects/P/gen_sound.py
.venv/bin/python scripts/sound.py P
.venv/bin/python scripts/audiocheck.py P
```

无配乐模式允许 `music: []` 或仅有 `type: "air"` 的轻底噪；`underwater`、`rain` 等环境声放 `sfx`。字段名 `music` 是内部总线名，不代表一定要加音乐。默认不读取 TTS 台词；在复用旧项目时检查有没有遗留的 `audio/voice.wav`，无配音输出可用 `sound.py P --solo`。

- `end` 与 `DURATION` 对齐，并留出需要的尾音；音频短于画面时渲染器会补静音，不截短画面。
- `lufs` 为目标响度，缺省 -14；`lufs: null` 保留原始编排音量。稀疏音效可跳过归一化或降低目标，不为凑响度制造持续噪声。
- 输出日志显示归一化后的实测响度与限幅量。WAV 样本峰值限制到 -1 dBFS；AAC 编码后的真峰值还需单独检查。
- `mute` 只切 `sfx` 总线，`automation` 调整 `music` 总线；若要完全静音，两条总线都处理，有配音时再处理人声。
- `audiocheck.py` 的响度、频段和疑似咔哒用于诊断；疑似点击可能是故意的冲击音。它不替代试听，也不是自动通过/失败裁决。

用户要求配音才运行 `voice.py`。它使用联网的 Edge TTS 服务，并将台词文本发送到该服务；生成 `audio/voice.wav` 与时间轴后再编排声音。原有台词、读音与逐词时间需复核。

## 渲染、续跑和改片

先跑小片段估时：

```bash
node scripts/render.mjs --proj P --video --from 0 --to 2 --chunk 1 --concurrency 2
```

正式成片：

```bash
node scripts/render.mjs --proj P --video --concurrency 2
```

默认每 20 秒渲一个 ProRes 片段，最后合成 H.264/AAC MP4。`--budget 520` 是片段之间检查的软预算，单块可能超时；需要更快暂停时减小 `--chunk`。退出码 3 是预算暂停，2 是仍缺片段，其他非零码按日志修错。暂停后用相同区间、块长和参数续跑。

`chunks/<画面指纹>/` 按源码、字体、时间轴、public 素材和画面编码设置区分缓存。修改画面会自动使用新目录，旧片段保留；只改 `post.json`、音效或混音可以复用原始片段：

```bash
node scripts/render.mjs --proj P --video --encode-only
```

`--encode-only` 会检查所需片段；画面输入改动后应重新渲染。完整输出是 `projects/P/P.mp4`，局部测试输出带起止帧编号。不要用部分测试片替代完整交付。`--clean` 停用；清理前列出具体待删文件，获得用户授权后逐项删除。

## 最终 MP4 的验收

渲染器先编码到临时 MP4，检查帧数并完整解码后才替换最终成片；中断时原成片保留。额外核对输出规格与最终音频：

```bash
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,nb_frames,duration:format=duration -of json 'projects/P/P.mp4'
ffmpeg -v error -xerror -i 'projects/P/P.mp4' -f null -
ffmpeg -hide_banner -i 'projects/P/P.mp4' -af ebur128=peak=true -f null -
ffmpeg -v error -ss 1.2 -i 'projects/P/P.mp4' -frames:v 1 'projects/P/final-1.2.png'
```

选开头、各转场前后、高潮、尾帧从成片抽图，逐张或拼图查看。编码前静帧正确不能证明成片没有截尾、字幕闪现或声音错位。实际播放试听后再描述听感；不能试听时说明只做了测量。交付时给出用户要求的最终文件及实际检查结果。
