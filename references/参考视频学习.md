# 参考视频学习与沉淀

目的：用户传一段喜欢的视频，用它建立可复用的视觉语言，再用这套方法表达别的主题。最终留下可以读取的风格文档、能复用的组件或工程和可以运行的原创示例。

## 1. 确定学习的范围

- 接收本地视频路径、可读取的附件，或可访问的视频链接。链接先确认能实际观看；无法获取视频时说明限制，并请用户提供可读取素材。只有截图时可以分析静态视觉，运动、节奏和声音暂时不作已验证结论。
- 用户说清楚要模仿的部分就沿用；只说“学这个风格”时，先学习视觉语言、运动和转场，字幕与声音单独记录。视频包含多种风格或很长时，选择连贯的代表区间，说明时间范围；有关键歧义再问。
- 新片的主题、定稿台词、人物和输出要求继续按用户请求执行。模仿画法、运动和节奏时，保留用户指定的人物身份；不把参考人物、对白、标志或剧情默认搬进新片。
- “模仿做片”对应一次制作；“学习/沉淀/加入库”包含试片、验证和入库；“只分析”先交分析。学习模式不自动上传用户参考素材，也不自动发布以后做出的新片。

## 2. 采样，留下可复查的证据

原文件保持不变，采样输出默认位于被 Git 忽略的 `studies/<id>/<批次>/`。

先做总览（只需 Python 标准库、FFmpeg 和 ffprobe）：

```bash
python3 scripts/study_video.py '/绝对路径/参考视频.mp4' --name amber-ink --frames 12 --audio
```

只学习一个区间：

```bash
python3 scripts/study_video.py '/绝对路径/参考视频.mp4' --name amber-ink --start 5 --end 25 --frames 12
```

观察转场时密集取样；关键材质帧需要原尺寸时，使用 `--width 0`：

```bash
python3 scripts/study_video.py '/绝对路径/参考视频.mp4' --name amber-ink --start 8 --end 9 --frames 12
python3 scripts/study_video.py '/绝对路径/参考视频.mp4' --name amber-ink --times 8.1,8.3,8.6 --width 0
```

输出包含：

- `study.json`：原文件 SHA-256、路径与规格、分析区间、取帧时间、生成文件清单。帧率由 ffprobe 报告，不凭此认定视频为固定帧率。
- `frames/*.png`：按源视频绝对时间取样，默认缩到不超过 960px 宽以便查看；`--width 0` 保留解码画面尺寸。视频旋转按 FFmpeg 的显示方向处理，不裁切。
- `sheet.png`：带时间码的总览，保留长宽比并留边。
- `reference-audio.wav`：仅 `--audio` 且原视频有音轨时提取所选区间，便于试听；时间码起点见 `study.json`。

总览只是找特征的入口。打开关键帧，实际播放代表片段；对起步、落定、回弹、转场中段再密集抽帧。不能从均匀取样的 12 张静帧判断全部运动。只看了部分区间就写明覆盖范围；没有听过音轨就把声音列为未验证。

图上的时间是请求取帧的源时间点；解码帧可能落在邻近帧，尤其是可变帧率素材。精确运动时序要结合连续播放和源帧时间检查，不把采样标签当成逐帧测量结果。

## 3. 拆成可操作的规则

写 `studies/<id>/<批次>/analysis.md`。用“观察 → 规则 → 实现 → 验证”的表格记录，避免只堆“高级、电影感、很有氛围”之类形容词。

| 维度 | 需要回答的问题 |
|---|---|
| 构图与层次 | 主体多大、放在哪，前/中/后景怎样分，字幕和留白在哪？ |
| 色彩与光 | 基础色和强调色是什么，最亮处在哪，亮区占多少，光是否跟主体走？ |
| 材质与造型 | 像素、剪纸、墨线、颗粒、实拍等可见特征是什么，边缘与细节怎样处理？ |
| 字体与字幕 | 字体类别、相对字号、行宽、位置、进入/离开方式、强调规则是什么？精确字体名无法确认就写近似选择。 |
| 运动与镜头 | 位移、旋转、缩放是否连续，是否跳帧，有无过冲/回弹，镜头如何推拉或跟随？ |
| 转场 | 前后什么元素在延续，中间怎样遮挡、形变或切换，持续多久？ |
| 节奏与叙事 | 镜头通常停多久，钩子如何出现，哪里加速、哪里停顿，变化怎样推进意思？ |
| 声音 | 哪个动作与哪种声音同步，是否有环境、配音或配乐？只写实际试听到的现象。 |

每个关键规则附具体时间码。例如“00:08.10–00:08.55，卡片先超过目标尺寸，再回到落点”，而不是“可能用了弹簧”。可见动作是观察；`spring()`、CSS、GLSL 或实拍灯光等制作机制是推测；只有原创试片验证过，才写成已验证的实现方法。

提炼 3–5 个最能认出风格的特征作为试片检查项。没有测量就不用编造精确参数：先给区间或近似，再在试片中调整。参考中偶发的道具、背景或角色不自动变成每条片子的必需元素。

## 4. 做一段可迁移的原创试片

在 `projects/示例_<id>/` 做约 10–20 秒试片；用户指定其他时长时按其要求执行。采用不同主题、道具和文案，覆盖刚才选出的关键特征，避免只复刻参考的单个镜头。

先按 [工具选择](工具选择.md) 确定实现。Remotion 路线在示例中试出画法，再将实际重复使用的能力提到 `src/styles/<id>/`；三维或混合路线保存实际使用的工程、脚本和渲染设置。一开始无需建设复杂的框架；调色板、背景层、一个文字组件和一个有辨识度的转场，若已够用就保持简单。可复用既有 `@kit`，但不要为了省事把明显不同的参考硬塞进 19 套内置风格。

参考需要实拍、纹理或模型素材时，用原创或用户授权的素材实现，并记录本地文件和来源。暂时拿不到必要素材、做不出关键运动或只能实现局部效果时，在本地记录候选方案与缺口；不做成“已经完全掌握”的风格。

按所选工具检查项目与静帧，再检查完整编码和解码；Remotion 命令见 [制作与验收](制作与验收.md)。初次试片用 1080p 以内预览，先估渲染负载；不要用未经检查的静帧代替运动验收。

## 5. 对照检查并沉淀

在本地分析中保留对照表：

| 特征 | 参考时间码与可见现象 | 原创试片时间码 | 差异与调整 | 结果 |
|---|---|---|---|---|

按此前选定的辨识特征逐项检查。构图/色光/材质看静帧；速度、回弹、运动连贯性和转场看连续片段；声音对齐靠实际试听。无需给没有依据的“相似度 92%”。用户主动反馈不满意时，根据具体差异迭代；普通完整学习流程可以自行验证完成，不需要反复询问“这样行吗”。

用户要求沉淀时，验证完成后留下：

1. `references/风格_<id>.md`：适用题材、辨识特征、可操作参数、分层与坐标、组件用法、声音选择、已知局限和验证范围。
2. 实際可复用的实现：Remotion 路线用 `src/styles/<id>/index.ts` 或 `index.tsx` 及所需着色器；其他路线用经过验证的工程、脚本、素材与设置。
3. `projects/示例_<id>/`：原创试片、`brief.md`、字幕/节拍、需要的声音编排和可重跑命令。Remotion 路线包含 `Main.tsx` 与 `post.json`；其他路线保留对应源工程。示例不依赖本地参考视频或未发布的抽帧才能运行。
4. [风格库](风格库.md) 中的索引行：ID、中文名、文档、所用工具与实际实现、示例。之后用户说“用 <中文名> / <id> 做片”时，读取这组资源。

风格文档在顶部标记“已验证范围”，例如“由 30 秒参考区间提炼，15 秒原创试片验证了纸纹、字幕弹入和翻页转场；人声与复杂角色动作未覆盖”。源视频是私人素材时，公开文档使用特征描述和时间码，不写本地私密路径，不附原视频、抽帧或音轨；有公开来源且用户允许公开引用时附链接。

入库前检查风格名不冲突、示例能运行、相对链接存在、实际实现被示例使用、关键结论有证据、没有未验证的实现宣称。通过再登记；未通过只保留 `studies/` 里的候选分析与项目试片，说明还差什么。
